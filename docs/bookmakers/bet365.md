# Bet365 integration

## Decision

The first real bookmaker connector targets **Bet365 through Sportradar Odds Comparison
Prematch v2**. The connector does not call, scrape, reverse-engineer, or automate Bet365
web or mobile properties.

This boundary is deliberate. Bet365's current customer terms prohibit automated systems
or software from copying/extracting service data including fixture lists and betting odds.
Accordingly, direct website extraction is out of scope for OddsAggregator.

Sportradar is used as the permitted provider boundary. Its Odds Comparison Prematch v2
documentation describes an authenticated odds API and currently lists `Bet365.US.NJ`
(book id `28901`, represented by API payloads as `sr:book:28901`) among the supported
bookmakers for the US-focused prematch package.

## Authentication and entitlement

Production network access requires a legitimately issued Sportradar API key with the
appropriate Odds Comparison entitlement. Configure the key outside source control, for
example through `SPORTRADAR_API_KEY`, and pass it to `Bet365SportradarConnector`.

The connector's `health()` operation calls Sportradar's Books resource and reports a
configuration error unless the configured API key actually exposes the expected Bet365
book. Possessing a generic Sportradar key is not treated as proof of Bet365 entitlement.

Supported Sportradar access levels are `trial` and `production`. No credentials, account
identifiers, or access tokens are stored in this repository or in test fixtures.

## Endpoints used

The adapter is restricted to documented Sportradar Odds Comparison Prematch v2
resources:

- `GET /books.json` for entitlement/health verification;
- `GET /sports.json` for source sports;
- `GET /sports/{sport_id}/schedules/{date}/schedules.json` for dated events;
- `GET /competitions/{competition_id}/schedules.json` for competition events;
- `GET /sport_events/{sport_event_id}/sport_event_markets.json` for markets and odds.

All HTTP I/O is asynchronous and uses an explicit request timeout. Event schedule
pagination uses the documented `start`/`limit` parameters and `X-Max-Results`, `X-Offset`,
and `X-Result` response headers when present.

## Rate limits and retries

Sportradar account quotas depend on the contracted product/access level and are not
hard-coded. The deployment must configure the shared per-bookmaker limiter according to
the actual Sportradar entitlement.

HTTP `429` is translated to `ConnectorRateLimitedError`; `Retry-After` is preserved for
the shared resilience layer. The connector never rotates API keys, identities, IP
addresses, sessions, or proxies to evade a quota. Authentication and authorization
failures are non-retryable shared connector errors.

## Normalization

The connector has stable `bookmaker_code = "bet365"` while retaining Sportradar
provenance in metadata.

- Sportradar sport/event IDs are preserved as source IDs for navigation through the feed.
- Sportradar sport `type` is a broad classification (for example `team`), not a unique
  sport code. The connector therefore returns `SourceSport.code = None` and retains the
  provider classification only as `metadata["provider_type"]`.
- Bet365 external market, event, and outcome IDs are preserved whenever Sportradar
  supplies them.
- `odds_decimal` is used directly and validated by shared DTOs.
- A removed/suspended Bet365 book market is represented as a suspended normalized market
  rather than as a parser failure.
- Removed outcomes remain present with `is_available = false` and no fabricated price.
- Malformed independent events/outcomes are isolated when valid sibling records can be
  trusted; structurally unusable markets are omitted instead of inventing identifiers.

## Current scope

This first reference connector is **prematch-only**. It does not claim Bet365 live/in-play
coverage. A live extension may be implemented only after the project's licensed
Sportradar account confirms Bet365 coverage in the relevant Live Odds product and its
rate/usage terms are documented.

The presently documented Bet365 entry is `Bet365.US.NJ`. Other Bet365 regional variants
must not be assumed. They can be enabled only when the licensed provider's Books endpoint
and commercial entitlement explicitly expose them.

## Testing

CI never calls Sportradar or Bet365. Sanitized synthetic fixtures under
`tests/fixtures/bet365_sportradar/` cover:

- configured Bet365 entitlement;
- sports and a normal prematch event;
- a malformed sibling event;
- Bet365-only market filtering;
- valid decimal odds;
- a removed/unavailable selection;
- a suspended market;
- missing optional external outcome IDs;
- malformed outcome isolation;
- pagination headers;
- rate-limit and temporary-server-failure bodies.

Repeated fixture reads are deterministic and exercise the reusable shared connector
contract harness.
