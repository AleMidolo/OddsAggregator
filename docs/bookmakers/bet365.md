# Bet365 integration

## Decision

The first real bookmaker connector targets **Bet365 through Sportradar Odds Comparison Prematch v2**. The connector does not call, scrape, reverse-engineer, or automate Bet365 web or mobile properties.

This boundary is deliberate. Bet365's customer terms prohibit automated systems/software from copying or extracting service data including fixture lists and betting odds. Direct Bet365 property extraction is therefore out of scope.

Sportradar is used as the permitted provider boundary. Its Odds Comparison Prematch v2 documentation describes an authenticated odds API and the repository's validated fixtures/configuration target `Bet365.US.NJ` (book id `28901`, represented in provider payloads as `sr:book:28901`).

References initially checked on 2026-09-09:

- Bet365 terms: https://help.bet365.com/s/en/terms-and-conditions
- Sportradar Odds Comparison Prematch overview: https://developer.sportradar.com/odds/reference/oc-prematch-overview
- Sportradar Books endpoint: https://developer.sportradar.com/odds/reference/oc-prematch-books
- Sportradar Sports endpoint: https://developer.sportradar.com/odds/reference/oc-prematch-sports
- Sportradar Daily Schedules endpoint: https://developer.sportradar.com/odds/reference/oc-prematch-daily-schedules
- Sportradar Sport Event Markets endpoint: https://developer.sportradar.com/odds/reference/oc-prematch-sport-event-markets

## Authentication and entitlement

Production network access requires a legitimately issued Sportradar API key with the appropriate Odds Comparison entitlement. Configure the key outside source control, for example through `SPORTRADAR_API_KEY`, and pass it to `Bet365SportradarConnector`.

The connector's `health()` operation calls Sportradar's Books resource and reports a configuration error unless the configured API key exposes the expected Bet365 book. A generic Sportradar key is not proof of Bet365 entitlement.

Supported configured Sportradar access levels are `trial` and `production`. No credentials, account identifiers, or access tokens are stored in this repository or fixtures.

## Endpoints used

The adapter is restricted to documented Sportradar Odds Comparison Prematch v2 resources:

- `GET /books.json` for entitlement/health verification;
- `GET /sports.json` for source sports;
- `GET /sports/{sport_id}/schedules/{date}/schedules.json` for dated events;
- `GET /competitions/{competition_id}/schedules.json` for competition events;
- `GET /sport_events/{sport_event_id}/sport_event_markets.json` for markets and odds.

All HTTP I/O is asynchronous and uses an explicit request timeout. Event schedule pagination uses the documented `start`/`limit` parameters and provider pagination headers when present.

## Rate limits and retries

Sportradar account quotas depend on the contracted product/access level and are not hard-coded. Deployment must configure the shared per-bookmaker limiter according to the actual entitlement.

HTTP `429` is translated to `ConnectorRateLimitedError`; `Retry-After` is preserved for the shared resilience layer. The connector never rotates API keys, identities, IP addresses, sessions, or proxies to evade a quota. Authentication and authorization failures are non-retryable shared connector errors.

## Normalization

The connector has stable `bookmaker_code = "bet365"` while retaining Sportradar provenance in bounded metadata.

- Sportradar sport/event IDs are preserved as source IDs for navigation through the feed.
- Sportradar sport `type` is a broad classification (for example `team`), not a unique sport code. The connector therefore returns `SourceSport.code = None` and retains the provider classification only as `metadata["provider_type"]`.
- Bet365 external market, event, and outcome IDs are preserved whenever Sportradar supplies them.
- `odds_decimal` is used directly and validated by shared DTOs.
- A removed/suspended Bet365 book market is represented as a suspended normalized market rather than a parser failure.
- Removed outcomes remain present with `is_available = false` and no fabricated price.
- Malformed independent events/outcomes are isolated when valid sibling records can be trusted; structurally unusable markets are omitted instead of inventing identifiers.

### M3 market-semantic conformance

`specs/connector-contract.md`, `specs/prematch-matching.md`, and ADR 0002 clarify that non-null `SourceMarket.market_type`, `SourceMarket.period`, and `SourceSelection.selection_type` values used for cross-source matching must be shared canonical semantic tokens, while provider display text remains in `name`/`label`.

The current reference implementation predates that clarification and may expose Sportradar/Bet365 display market text through `SourceMarket.market_type`. That output remains useful as source text for the already-validated one-source ingestion path, but **must not be treated as canonical cross-source market identity** until the connector is brought into conformance with the M3 semantic registry.

The required fix belongs inside the Bet365/Sportradar adapter, backed by explicit provider-to-canonical mappings and fixtures. The generic matching service must not learn Sportradar-specific labels or compensate for this adapter behavior.

If the provider semantics cannot be safely mapped, the adapter must leave the corresponding shared semantic field null/unsupported rather than guess.

## Current scope

This reference connector is **prematch-only**. It does not support or claim live/in-play coverage.

No live extension may be implemented merely because a provider offers a live product. A future live connector would require **both** an explicit Product Coordinator scope change and separately documented permitted provider entitlement/rate/usage terms. Until then, live endpoints and live product behavior are out of scope.

The presently documented Bet365 entry is `Bet365.US.NJ`. Other regional variants must not be assumed; they may be enabled only when the licensed provider's Books endpoint and commercial entitlement explicitly expose them.

## Testing

CI never calls Sportradar or Bet365. Sanitized deterministic fixtures under `tests/fixtures/bet365_sportradar/` cover:

- configured Bet365 entitlement;
- sports and a normal prematch event;
- a malformed sibling event;
- Bet365-only market filtering;
- valid decimal odds;
- a removed/unavailable selection;
- a suspended market;
- missing optional external outcome IDs;
- malformed outcome isolation;
- pagination headers;
- rate-limit and temporary-server-failure bodies.

Repeated fixture reads are deterministic and exercise the reusable shared connector contract harness. M3 cross-source market tests additionally require semantic-token conformance before this connector's market fields can participate in canonical market/selection matching.
